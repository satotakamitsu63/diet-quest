# ダイエットクエスト

食べたものを話しかけて記録すると、栄養の充足と目標体型への近さでドット絵のキャラクターが育つ、家族共有の PWA。

## できること

- 音声（または文字）で「ごはん二膳と鮭の塩焼き、納豆1パックと卵二個」のように話すと、食品と分量に分解して栄養素を積算する
- 年齢・性別・活動量から1日の目標量を算出し、13項目の充足率と 100 点満点のスコアを出す
- スコアと目標体型への近さでキャラクターが 10 段階に育つ。体型は BMI と体脂肪率から連続的にシルエットへ反映される
- 家族それぞれのキャラクターの様子を一覧で見られる
- 身長・体重が未入力でも、栄養の充足だけで動く

## 設計上の決めごと

**目標体型は BMI 22 を既定にしていない。** BMI 22 は統計上いちばん病気になりにくい体重であって、見た目の理想ではない。
既定は「理想体型」（男性 BMI 21.5・体脂肪率 14%／女性 BMI 20.0・体脂肪率 22%）で、
「健康維持」「アスリート体型」「フィジーク・審美系」「自分で決める」から選べる。
ただし目標 BMI は 18.5 未満、目標体脂肪率は男性 6%・女性 14% 未満には設定できない。必須脂肪を割り込むと
無月経・骨密度低下・疲労骨折を招くため。

**18歳未満には体重を減らす目標を設定しない。** 小児は日本小児内分泌学会の身長別標準体重から肥満度を出して
体型を表示するだけで、減量方向のエネルギー補正もかけない。バレエなど審美系競技をしている場合は
「審美系競技モード」を有効にすると、身体活動レベルを高い側で見積もり、鉄・カルシウム・ビタミンD・
たんぱく質の重みを上げる。成長期の低エネルギー相対性不足（RED-S）を助長しないための設計。

**子どもには身長の目標を置く。** 両親の身長から予測成人身長（男子 =（父+母+13）/2、女子 =（父+母−13）/2）を
計算し、目標身長として使う。手入力で上書きもできる。実際の到達身長は予測の前後およそ ±9cm に広がるため、
点ではなく幅で見せる。身長の記録が2か月以上あいだを空けて2つそろうと、1年あたりの伸びを計算する。

**成長期ブーストは「伸ばす」ためではない。** 18歳未満で有効にすると、たんぱく質・カルシウム・ビタミンDの
目標を推奨量より約2割厚くする（カルシウムは1日1000mg、たんぱく質は体重1kgあたり2.0gを上限）。
ただしカルシウム補充の小児 RCT のメタ解析では骨密度はわずかに上がるが身長は伸びず、たんぱく質も
推奨量を超えた分が遺伝的な到達身長を押し上げる根拠はない。目的は伸びしろを取りこぼさないことであり、
アプリの文言もその通りに書いてある。エネルギー目標はブーストで増やさない。

**痩せれば育つ仕組みではない。** キャラクターの経験値は「栄養スコア × 目標体型への近さ」で決まり、
摂取エネルギーが必要量の 70% を下回る日が 3 日続くと経験値が減り、キャラクターはやつれた見た目になる。

## 対戦

育てたキャラクターどうしで戦える。強さのもとは直近2週間の栄養の充足と記録の継続で、
そこに年齢・体型・部活・受賞歴の補正がかかる。

- **ステータスの由来**：たいりょく＝エネルギー、こうげき＝たんぱく質、ぼうぎょ＝カルシウムとビタミンD、
  すばやさ＝鉄とビタミンB1/B2、こんじょう＝食物繊維とビタミンC/A
- **年齢補正**：子どものほうが強い（9歳以下 +55%、10〜12歳 +45%、13〜15歳 +30%、16〜17歳 +15%、大人 ±0%）。
  体格差をそのまま持ち込むと子どもが勝てず続かないため
- **体型補正**：その年齢での目標体型への近さで決まる。**目標から離れるほど下がる左右対称の評価**で、
  太りすぎでも痩せすぎでも弱くなる。子どもの目標は身長別標準体重なので、食事を抜いて痩せると弱くなる
- **部活・習い事**：必殺技の名前と得意ステータスが決まる（バレエ＝グラン・ジュテ／すばやさ +12% など）。
  必殺技名は自分で決めてもよい
- **受賞歴**：規模ごとに点数がつき（校内1／地区2／県4／全国8）、スポーツ点・勉強点・芸術点として集計される。
  効果は合計20点・最大 +25% までで頭打ち

体重や体脂肪率そのもの、痩せているかどうかは強さに使わない。細いほど強い設計にすると、
ゲームが減量を促す装置になるため。食べる量が足りず「やつれ」状態になると全ステータスが下がる。
必要量を超えて食べた分も強さにはならない。

## 週ごとのふりかえり

ホーム画面に直近7日の振り返りが出る。

- **マイナス点**：1日ごとに、目標の50%未満なら−10点、70%未満なら−5点。
  記録がない日は−5点。まったく食べていない日でおよそ−100点になり、0〜100点のスコアと同じ桁で読める
- **具体的なアドバイス**：不足の大きい栄養素から3つ、実際に食べた記録をもとに直し方を出す。
  足す候補は1食分の量を盛りの大きさで割り引いて並べるので、「パスタを3皿」のような実行しにくい提案にならない。
  1品で埋まらないときはその旨を書く。食塩が多い週は、実際にいちばん食塩を持ち込んだ料理を名指しする

## 動かす

```bash
npm install
npm run dev
```

`npm run verify` で、パーサ・食事摂取基準・体型判定・スコア・ドット絵生成の動作確認が走る。

音声入力はブラウザの音声認識（Safari / Chrome）を使う。非対応の環境では文字入力に切り替わる。
iPhone では Safari で開き、共有メニューから「ホーム画面に追加」するとアプリとして使える。

### 実機（iPhone）で音声入力まで試す

ブラウザはマイクを「安全なコンテキスト」でしか許可しないため、`localhost` 以外は HTTPS が要る。

```bash
./scripts/make-cert.sh          # LAN の IP を含む自己署名証明書を作る
npm run dev                     # certs/ があれば自動で HTTPS になる
```

同じ Wi-Fi の iPhone から `https://<MacのLAN IP>:5173` を開く。
自己署名なので警告が出るので「詳細を表示 → このWebサイトを閲覧」で進む。
IP が変わったら `./scripts/make-cert.sh` を作り直す。
`certs/` を消せば HTTP に戻る（音声入力は使えなくなる）。

## 家族で共有する（Supabase）

未設定のあいだはブラウザのローカル保存で動く。共有するには次の手順を踏む。

1. Supabase でプロジェクトを作る
2. SQL Editor で `supabase/schema.sql` の内容を実行する
3. プロジェクト直下に `.env` を作り、URL と anon key を書く

```
VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY=xxxx
```

4. アプリを開き、メールアドレスでログインして「家族グループを作る」。表示された合言葉を家族に伝える
5. 家族は同じアプリでログインし、「合言葉で参加する」に入力する

行レベルセキュリティにより、同じグループのメンバーだけが互いの記録を読み書きできる。

## データの出どころ

- 栄養素の目標値：厚生労働省「日本人の食事摂取基準（2020年版）」（`src/data/dietaryReference.ts`）
- 食品の成分値：日本食品標準成分表2020年版（八訂）。料理は標準的なレシピからの目安値で、
  `source: 'recipe'` として区別している（`src/data/foods.ts`）
- 小児の標準体重：日本小児内分泌学会 性別・年齢別・身長別標準体重（`src/data/childStandardWeight.ts`）

いずれも1ファイルにまとめてあるので、値を差し替えればアプリ全体に反映される。
食品を足すときは `FOOD_ROWS` に1行加えるだけでよい。

医療行為の判断に使うものではない。

## 個人情報の扱い

- 名前・身長・体重・体脂肪率・食事の記録は、**使っている人のブラウザの中だけ**に保存される。
  このリポジトリにも、配信元のサーバにも送られない
- Supabase を設定した場合にかぎり、自分で用意したデータベースに保存される。
  行レベルセキュリティにより、同じ家族グループのメンバーだけが読み書きできる
- 外部の解析サービス・広告・トラッキングは一切入れていない。外部への通信は Supabase を
  設定したときのその接続だけ
- このリポジトリにコミットされているのはプログラムと公開データ（食品成分表・食事摂取基準）
  だけで、実在する個人のデータは含まない
